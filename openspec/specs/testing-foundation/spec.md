## Requirements
### Requirement: Four-layer test pyramid

The orchestrator SHALL adopt four test layers: unit (Vitest), component (Vitest + RTL + jsdom), integration (Vitest + RTL + MSW), and end-to-end (Playwright + MSW service worker). Each layer MUST run via a moon task.

#### Scenario: Tasks invoke their layer

- **WHEN** `moon run orchestrator:test` runs
- **THEN** Vitest executes unit, component, and integration suites under jsdom

#### Scenario: E2E runs separately

- **WHEN** `moon run orchestrator:test-e2e` runs
- **THEN** Playwright starts the dev server, registers the MSW service worker, and runs the smoke spec

### Requirement: Shared MSW handlers

A single set of MSW handlers in `src/mocks/handlers/` SHALL serve both Vitest (Node) and Playwright (service worker). The set MUST cover `POST /auth/login`, `POST /auth/logout`, `GET /auth/me` minimally.

#### Scenario: Same handler resolves login in both layers

- **WHEN** a Vitest integration test and a Playwright test both call `POST /auth/login` with valid credentials
- **THEN** both receive a `200` response generated by the same handler module

#### Scenario: Handlers reusable per test

- **WHEN** a test needs to override a single endpoint
- **THEN** it calls `server.use(customHandler)` (Node) or `worker.use(customHandler)` (browser) without mutating the shared set

### Requirement: renderWithProviders helper

`src/test/renderWithProviders.tsx` SHALL wrap components under test with the same Query client, Router, and i18n providers used in production. The helper MUST accept an optional `initialRoute` and per-test query client.

#### Scenario: Component test uses the helper

- **WHEN** a Vitest test renders `<LoginForm />`
- **THEN** the component sees a real QueryClient and i18n instance via `renderWithProviders`, not partial mocks

### Requirement: One Playwright smoke E2E

This change SHALL include exactly one Playwright spec covering login → authed landing. The spec MUST drive the form, observe the `/auth/me` MSW response, and assert that the authed landing route mounts.

#### Scenario: Smoke flow passes

- **WHEN** `moon run orchestrator:test-e2e` executes the smoke spec
- **THEN** it logs in via the rendered form and asserts that the authed landing placeholder is visible

### Requirement: Coverage thresholds

Vitest SHALL enforce 80% line coverage on `src/lib/`, every module's `api.ts`, `hooks.ts`, and `schemas.ts`. Below threshold, CI MUST fail.

#### Scenario: Coverage gate

- **WHEN** a PR drops coverage on `src/lib/api/` below 80%
- **THEN** the Vitest run exits non-zero and the moon CI pipeline fails

### Requirement: Agentic testing conventions documented

`apps/orchestrator/AGENTS.md` SHALL document the agent-facing testing workflow: write tests first when the change is non-trivial, run `moon run orchestrator:test` before claiming completion, and never disable a test to make CI green.

#### Scenario: Agent runs tests before claiming done

- **WHEN** an agent finishes a task touching `src/modules/auth/`
- **THEN** it MUST run `moon run orchestrator:test` and report the result before marking the task complete
