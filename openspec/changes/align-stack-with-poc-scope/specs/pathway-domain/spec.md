## ADDED Requirements

### Requirement: Pathway model

The backend SHALL define a `Pathway` model with `id`, `name`, `owner_id` (FK to `User`), `created_at`, `updated_at`, and a `blocks` JSON column storing an ordered list of block objects. The block list MUST be parsed through a Pydantic discriminated union on read so unknown block kinds raise a typed `AppError`.

#### Scenario: Pathway round-trip

- **WHEN** a service inserts a `Pathway` with three blocks and reads it back
- **THEN** `blocks` is a list of three Pydantic block models in the original order
- **AND** unknown block kinds in the stored JSON raise `AppError("pathway.invalid_block_kind")`

### Requirement: Block kinds (PoC set)

The backend SHALL define exactly these block kinds in the PoC discriminated union: `appointment`, `decision`, `milestone`, `email`, `hix_task`, `luscii_care_path`. Each block kind MUST carry an `id` (uuid) and `kind` discriminator. The `luscii_care_path` block MUST carry a `static_payload: dict` field — its content is opaque to the orchestrator.

#### Scenario: Luscii block treated as opaque

- **WHEN** code outside `app/adapters/luscii/` reads a `luscii_care_path` block
- **THEN** it accesses only `id`, `kind`, and `static_payload` without parsing the payload contents

#### Scenario: New block kind rejected

- **WHEN** stored JSON carries `kind: "video_call"` (not in PoC set)
- **THEN** load fails with `AppError("pathway.invalid_block_kind")`

### Requirement: Patient model

The backend SHALL define a `Patient` model with `id`, `display_name`, `birthdate`, `created_at`. Patients are seeded synthetic data in PoC — no real patient data may be inserted.

#### Scenario: Patient creation in tests

- **WHEN** a test fixture inserts a `Patient`
- **THEN** the row persists and is retrievable by id

### Requirement: PathwayEnrollment model

The backend SHALL define a `PathwayEnrollment` with `id`, `pathway_id`, `patient_id`, `current_block_id`, `completed_block_ids: list[str]`, `enrolled_at`. A patient MUST have at most one active enrollment in PoC (unique constraint on `patient_id` where `completed_at is null`).

#### Scenario: One pathway per patient

- **WHEN** a service tries to enroll a patient who already has an active enrollment
- **THEN** the operation raises `AppError("enrollment.already_active")`

### Requirement: Task model

The backend SHALL define a `Task` with `id`, `enrollment_id`, `block_id`, `title`, `status: pending|done`, `completed_at`, `completed_by` (FK to `User`). Tasks are generated by the runtime when an enrollment advances onto a task-producing block.

#### Scenario: Task transitions to done

- **WHEN** a service calls `complete_task(task_id, user_id)`
- **THEN** `status` becomes `done`, `completed_at` is set to UTC now, `completed_by` records the user

### Requirement: Linear runtime

The backend SHALL provide a deterministic linear runtime: on enrollment, `current_block_id` is the first block; on task completion, the runtime advances `current_block_id` to the next block in `Pathway.blocks` order and appends the previous block id to `completed_block_ids`. Decision blocks render but do not branch in PoC — the runtime advances past them as if linear.

#### Scenario: Advance on task completion

- **WHEN** the only pending task for an enrollment is completed
- **THEN** `current_block_id` advances to the next block in saved order

#### Scenario: Decision block advance

- **WHEN** the current block is a `decision` and the user advances it
- **THEN** the runtime advances to the next block (no branching in PoC)

### Requirement: Alembic migration baseline

The backend SHALL ship an Alembic baseline migration that creates every table above. `alembic upgrade head` MUST succeed against an empty SQLite file with no manual steps.

#### Scenario: Fresh DB upgrade

- **WHEN** CI runs `alembic upgrade head` against `sqlite+aiosqlite:///:memory:`
- **THEN** all migrations apply with exit code 0

### Requirement: Persistence settings

`Settings.database_url` SHALL default to `sqlite+aiosqlite:///./poc.db` for dev and be overridable via `BACKEND_DATABASE_URL`. Tests MUST default to `sqlite+aiosqlite:///:memory:`.

#### Scenario: Test override applies

- **WHEN** `pytest` runs with the default conftest
- **THEN** the engine resolves to in-memory SQLite, isolated per session
