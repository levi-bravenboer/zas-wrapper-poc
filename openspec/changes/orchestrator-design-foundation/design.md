# Design notes — orchestrator-design-foundation

## Why these specific decisions

### Why oklch and not hex in tokens

Tailwind v4's `@theme` accepts any CSS color value, but oklch gives perceptually-uniform lightness, which matters when we derive a hover/pressed scale off the same hue. Hex is documented inline (`/* #266b5e — ZAS primary */`) so a designer auditing the file can trace each token to the ZAS source without reverse-engineering oklch.

### Why keep `--color-muted-foreground` as alias

shadcn templates generated by `shadcn add <name>` reference `text-muted-foreground` heavily. The semantic name we want long-term is `--color-foreground-muted` (subject-modifier order). Aliasing `--color-muted-foreground: var(--color-foreground-muted)` lets generated templates compile unmodified while we keep the cleaner semantic name as canonical. Cost: one line. Avoided cost: hand-editing every template's class list.

### Why drop `--color-secondary` and `--color-accent`

Linear-style restraint is the visual posture (Q3 in brainstorming). Linear's palette is essentially `primary + neutrals`; "secondary" and "accent" as separate semantic colors fight that posture and create more variants for every primitive (`Button` would gain `secondary` + `accent` variants that nothing in the PoC actually wants). Folding both into `--color-surface-2` (neutral surface) + `--color-primary-soft` (the existing tinted-primary slot) preserves what shadcn templates use those tokens for (hover backgrounds) without giving designers a third color to reach for.

### Why drop the `[data-theme="dark"]` block entirely instead of leaving it

The block exists today as ~35 lines of dark token values that nothing reads (the spec forbids `dark:` Tailwind variants in components, and there is no toggle UI). Leaving it pretending to be "ready" creates a false signal: a future contributor adding a dark mode would think the work is half-done and ship inconsistent dark values. Deleting it makes the future-dark-mode change own the entire posture decision honestly. The spec's existing "Token swap is the only thing needed for dark mode" scenario stays true — whoever adds dark mode adds the block.

### Why Geist over Inter

Q5 picked Geist. Geist is Vercel's variable font, designed for code-adjacent UI; the Mono pairing feels native. Inter is more battle-tested but the Linear-vibe goal is "modern 2026 cool", and Geist is the more current pick. Self-hosted via `@fontsource-variable/geist` so there is no Google Fonts CDN call (Belgian-healthcare GDPR posture).

### Why no Storybook

PoC pace, single product surface, every primitive is a thin Radix wrapper that already has accessibility tested upstream. Visual verification is `moon run orchestrator:dev` plus the existing component tests asserting behaviour. If component count grows past ~30 or the team grows, revisit.

### Why no specialty libraries in this change

Q1 picked B-as-posture / "not now". The pathway-builder DnD library, virtualised table library, chart library each pull in their own primitives, opinions, and bundle weight. Bundling them with the design foundation would either commit to libraries before any feature confirms the choice (DnD-Kit vs. dnd-kit-sortable vs. Pragmatic-DnD all valid for `F3`) or let the foundation change drag indefinitely. Per-feature changes pick the lib when the feature lands.

## Risks

- **shadcn template drift.** `pnpm dlx shadcn add` may emit components with subtly different class lists than `Button.tsx`/`Card.tsx` were generated with. Mitigation: hand-port each new primitive to match the existing primitives' style (named export, cva variants, `cn` from `@/lib/style`, no raw strings). The `add` command is convenience; the artefact is ours.
- **Geist subset weight.** Variable fonts can be 80–150 KB before subsetting. Mitigation: confirm bundle delta in step 9.4 of `tasks.md`; if > 150 KB raise as a follow-up to subset Latin only.
- **Existing primitive re-skin uncovers a deeper variant.** If `Button.secondary` is used somewhere we miss in the grep, runtime classes resolve to nothing and the button looks broken. Mitigation: `moon run orchestrator:dev` + manual `/login` (and any other route that mounts) is in the gate; component tests are not pixel-aware.

## Alternatives considered (and rejected)

- **Three smaller changes (tokens → typography → primitives).** Cleaner audit trail; rejected for PoC pace and risk of mid-tree visual inconsistency.
- **Whole UI kit (Mantine / Chakra) layered alongside shadcn.** Heavier; conflicts with the existing `design-system` spec's shadcn-copy-in stance.
- **Inter instead of Geist.** Battle-tested but less of the modern 2026 feel the brief asks for.
- **Keep dark token block as scaffold.** Misleading signal; deleting forces honesty when dark mode is actually proposed.
