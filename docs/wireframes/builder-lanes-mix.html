Variant

Mix model · 4 default lane kinds + custom + override

How it works

  • 4 default lane kinds seeded in lane_kind: Patiënt, Zorgverlener, Systeem, Extern. Each block type declares one as its default_lane_kind.
  • Default lanes materialize as pathway_lane rows on first use (is_default = true).
  • Custom lanes are added by the author (e.g. Apotheek under the caregiver kind). Stored as pathway_lane with is_default = false and an overridden label.
  • Override: drag any block into another lane → pathway_block.lane_id updates. Always non-NULL.
  • Integration (HiX, Luscii, Email) is a chip on the block, not a lane — keeps the canvas readable.

Legend

default — seeded lane kind, auto-shown when used
custom — author-added (sub-role of a kind)
moved — block placed outside its default lane

Data model (locked, D10)

lane_kind          -- system catalogue
  id text PK       -- patient | caregiver
                   -- system  | external
  label_i18n
  color_token
  default_ord

pathway_lane       -- per-pathway instance
  id uuid PK
  pathway_id FK
  kind_id FK -> lane_kind
  label            -- override per pathway
  ord
  is_default

pathway_block.lane_id NOT NULL
  -> pathway_lane

Adding a new lane kind = seeded migration row. No deploy-coupled enum.
